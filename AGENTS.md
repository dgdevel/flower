# AGENTS.md

Working instructions for coding agents (and humans) in this repository.

## Project

flower — a single-binary webapp in C11. The frontend is plain HTML/CSS/JS
in `web/`, embedded into the executable at build time. See README.md for
the architecture, HTTP surface, and design decisions.

## Build, run, test

```sh
make            # build ./flower (regenerates embedded assets when web/ changes)
make run        # build + serve on 0.0.0.0:8080
make check      # API/protocol smoke tests (tests/smoke.sh, isolated config dir)
make clean
./flower -p PORT -b ADDR -c CONFIG_DIR
```

## Browser testing — playwright via bunx, FIREFOX ONLY

`bun`, `bunx` and playwright (1.63+) are available. **Only Firefox may be
used** — system dependencies for chromium/webkit are not guaranteed to be
installed in this environment. Never pass `--browser chromium|webkit` or
`--device` profiles that imply another browser engine.

Everything playwright-related stays inside the repository: browsers are
installed into the gitignored `.playwright/`, and the test server uses the
throwaway `.e2e-config/` dir. Do not install browsers into `/tmp`, `$HOME`
or anywhere else on the host — `/tmp` is wiped between sessions.

```sh
tools/e2e.sh setup     # one-time per clone: firefox -> .playwright/

tools/e2e.sh ff http://127.0.0.1:8080/   # interactive inspector
tools/e2e.sh test --project=firefox      # e2e suite: playwright.config.ts
                                        # starts ./flower on :8120 (make first)
bunx playwright test --project=firefox   # equivalent; playwright.config.ts
                                        # also points at .playwright/
```

No image extraction/viewing feature is available, view_image will not work.

## Code conventions

- C11, compiled with `-Wall -Wextra -Wpedantic`; POSIX only. JSON goes
  through the system cJSON (`#include <cJSON.h>`, linked via pkg-config
  `libcjson`). New persisted settings follow the `src/theme.c` /
  `src/projects.c` pattern: lenient load, strict validated save, atomic
  tmp+rename write, files under the config dir (see `theme_dir()`).
- Working directories in projects.json must exist on disk: PUT validates
  with `stat()`, GET reports a live `exists` flag, and the UI blocks
  columns two/three while the selected project's directory is missing.
- Frontend: no build step, no external dependencies; plain files in
  `web/` are picked up by the asset embedder automatically. Use relative
  URLs (`api/...`, `style.css`) so pages work behind path-prefixed
  proxies. Theme colors/sizes/fonts come from CSS custom properties —
  never hardcode a color in a component. `web/emoji.js` is GENERATED by
  `tools/emoji.py` from Unicode's emoji-test.txt — regenerate, don't edit.
- Keep `make check` and `tools/e2e.sh test --project=firefox` green
  before committing.
